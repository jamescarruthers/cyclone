9246: Death sequence (helicopter destroyed)
Entered from the main loop when 7505=1. Plays a 24-step explosion animation in the view, marks a life as lost (helicopter icon turned red), and either returns to the menu (3 lives lost) or resets the per-life variables and resumes the main loop at 5B36. OBSERVED: the 24 steps take about 132 frames (2.6 s).
Per step (counter n = 24 down to 1): 76D2 rebuild view buffer, 8B91 waves; 6950 = 72 zero bytes (copied from 9300); n >= 22: 8CA0 rebuilds the normal helicopter sprite; n = 18: 752D+1 (explosion sound request for the interrupt handler); n >= 20: XOR the next explosion overlay (F550+72*k, k=0..4) onto 6950; then 7E10 (tile stacks), 86AF (draw sprite), 762C (render view). So the explosion overlays are shown over the helicopter for steps 24-22, alone for steps 21-20, and the sprite is blank from step 19.
Life lost: attributes (row 10+2*k, columns 24-25), k = lives lost so far, are set to $02 (red ink); lives lost +1; 3 = game over (JP E280). Otherwise 82A7 (fuel-gauge tick) is called until 7516=1 (fuel gauge emptied), then every byte of the reset table 75C8-762B that is not $FF is copied over 7500-7563 (position $0139,$0170 on the base pad, landed, altitude 8, speed 0 ...; $FF entries such as the time bar pointer 751C/751D, 7543-754C markers/cyclone, 754E/754F, 7554 crates are kept) and play resumes at 5B36.
